# CPU 偏高诊断

1. 先记录宿主机负载、容器 `docker stats --no-stream` 与 JVM `dashboard`，区分主机压力、容器配额/节流和 JVM CPU。
2. 使用 `thread -n 10` 识别热点线程，保留线程 ID、状态、栈和采集时间；重复短间隔采样确认持续性，不以单次快照定论。
3. 只有目标仍确认且 L1 证据指向 JVM 计算热点时，才做有界 profiler 采样。默认不超过 30 秒，单 JVM 单活动任务，确保能 stop。
4. 能安全输出时保存 Arthas profiler 结果/火焰图；没有既有可写输出位置时跳过文件型采样，采用低开销文本检查并报告限制。
5. 分析热点占比、调用树、线程和业务代码证据。说明采样代表性及负载条件；不要把采样关联直接表述为已证明的根因。
