# Java 与 Arthas Attach 兼容性

在 Arthas 上传或 Attach 前完成检查，并保留“兼容 / 有条件兼容 / 不兼容 / 未能判定”及证据。不要把一次探测失败当成环境必然不兼容。

## 检查项

- Linux OS、CPU 架构、Java 版本和目标 JVM 实际 Java 路径。
- 容器内 PID 与宿主机 PID namespace 的对应关系；进程是否仍是已确认目标。
- JVM UID/GID 与诊断进程 UID/GID 是否一致，Attach 文件/信号是否可访问。
- JVM Attach 相关文件、动态 Attach 设置、容器安全策略及 `/proc` 可见性。
- Arthas 运行所需的临时目录及其权限、空间；这与报告输出目录分别验证。
- 容器只读根文件系统、已有 `/tmp` 或其他现存可写 mount、磁盘余量、容器 CPU/内存限制。
- 报告文本/二进制文件的落盘或 stdout 回传能力。

缺少 `jcmd` 不等于 Attach 一定失败；缺少 shell 也不自动等于不兼容。描述已验证事实、未知项和安全可行的下一项探测。若无法确认 Attach 安全、目标 PID 身份或必要写入位置，应停止相应操作。

## 输出判定

- **兼容：** 目标、Attach 条件及所需输出方式均经验证。
- **有条件兼容：** 明确列出使用哪个已存在目录、运行用户或仅 stdout 的降级方案；不得要求改变生产配置。
- **不兼容：** 已确认存在不可满足条件，停止部署/诊断并给出证据。
- **未能判定：** 探测受限，说明限制；不宣称不兼容，也不冒险 Attach。
