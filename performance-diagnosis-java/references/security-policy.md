# 生产安全策略

## 不可突破的限制

- 目标 host、容器、PID 分别由执行人明确选择；容器重启或身份改变需重新确认。
- 复用 SSH alias，不读取/传输私钥，不关闭 Host Key 校验，不自动改 SSH 配置，不自动 sudo。
- 生产环境不修改业务数据、代码、配置、JVM 参数或容器配置；不重启/停止/杀进程。
- 不动态添加挂载、不重建容器、不关闭只读文件系统、不改业务目录权限。
- 不采集 Heap Dump，不动态修改业务类，不执行无法限时/限量的插桩。
- 只使用白名单诊断能力；不得把任意自然语言直接拼成远程 shell 命令。
- 诊断输出需脱敏 Token、密码和密钥；不完整采集环境变量；文件仅当前用户可访问。

## 等级与停止条件

L1：确认目标后可做低开销只读采集。L2：限目标、次数、输出和时长（profiler 单次最长 5 分钟），且必须有可靠停止方式。主机/容器近期 OOM 或容器内存达到 limit 的 80% 时，默认推荐不执行 L2；可由执行者选择“强制启用 L2（承担风险）”，但必须单独确认具体风险、目标、操作及时长/次数，且记录风险接受。该确认不消除运行风险。L3：v1 禁止自动执行。若工具边界无法保证目标绑定、只读、超时、停止或清理归属，则停止该步骤并说明原因。

Attach 和采样会给目标 JVM 带来一定运行时开销；报告应记录操作、时长和限制，不能声称完全无副作用。
