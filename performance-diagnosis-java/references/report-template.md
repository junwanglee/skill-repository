# 报告内容规范

最终报告基于 `templates/performance-report.md`。所有结论分为已证实、较强迹象、待确认，并逐项引用原始文件/命令输出。写明不能诊断的环节，避免把缺失数据当成正常。

性能热点结论须落到代码：记录仓库及提交版本、类/方法、源码文件和行号、对应 profiler/trace/thread 证据、问题代码行为，以及优先级明确的优化方案、预期收益/风险和验证方法。源码不可访问时明确标注“待源码核实”，给出待检查的类、方法或调用栈；禁止猜测路径、行号或声称未经实施的改动已完成。

必须包含目标身份、诊断时间、问题类型、环境与资源、命令时间线、证据、根因候选及可信度、优化建议、未解决问题、附件清单、回传哈希校验和清理状态。所有输出脱敏。对比前后诊断时注明采样时长、负载和时间段差异；条件不一致时只做定性比较。
